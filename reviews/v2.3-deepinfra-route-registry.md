# A Route Registry for the Bootstrap Organism

**Document kind:** registry amendment proposal, input only. Not a review, not a paper revision.
**Paper version:** v2.3.
**Supersedes:** the 1:1 Ollama-to-DeepInfra substitution audit committed earlier in this session. The local registry in Appendix D is not the selection basis here; it is a record of what one host happened to hold. This document selects models against the paper's own criteria instead, and the original tags are disregarded.
**Snapshot:** DeepInfra catalog (`/v1/openai/models`, 178 entries) read 2026-11-07. Prices are per 1M tokens on that date, observations rather than pinned constants.

## 1. What the route changes

The paper assumes local inference is the baseline metabolism (§3 Law 1) and derives its model economics from the host: residency is cheap, activation is dear, decode is bandwidth-bound, KV is finite (§5.7). A paid route deletes that physics and substitutes three provider-side quantities: price per token, latency, and served context. The operator's reason for taking the route is sound — a CPU-only tower cannot boot a cognitive organism at interactive latency — but the consequence has to be stated: **the route is an emergency ration under Law 1, and a registry built on it is a constitutional exception, not an amendment to the metabolism.**

## 2. What the paper selects on, and what survives

Appendix D's own columns name the measurement battery ("tokens/s on 16 and 32 threads; watts/lane; actual KV growth curve; output quality on golden set"). Split those by whether a remote endpoint can supply them.

| Paper criterion | Source | On the route | What replaces it |
|---|---|---|---|
| Quality per joule per completed, verified task | Law 1, App. A `joules_task`, `usd_per_joule` | **Transforms** | Quality per **USD** per completed, verified task; `paid_dispatch` is already the ledger's USD line |
| Active parameters set velocity class | §5.7 | **Lost** (provider's scheduler) | Measured TTFT/TPOT from the endpoint, per prompt class |
| Residency rent; resident never routed is dead weight | Law 4, §5.7, App. D.4 | **Lost** (no rent) | Budget share; a route never selected is the §8 under-use alarm |
| KV growth caps usable context | §5.7, `kv_growth_mib_per_1k` | **Transforms** | Served context length, and cache-read price as the discount on re-reads |
| Bandwidth/NUMA ceiling; lane pinning | §5.7, Law 2, `bandwidth_gbs_<node>` | **Lost** | Nothing. Q9's hysteresis becomes provider cache eviction |
| Backbone divergence for the pair | §5.6 Rung 3, Law 3 | **Inverts** | Rung 3 no longer costs residency or thread share, so it is the *cheapest* divergent rung, not the last resort |
| Small lanes as myelination trial beds | §10 | **Transforms** | Cheapest adequate route is the trial bed; the script rung is worth more, since every token is billed |
| One context-heavy resident, not two | §5.7, App. D.4 | **Survives** | Cheapest 1M-context route, funded once |
| Model + version stamped on every learned claim | Law 5 | **Weakens** | Provider model id and version, not a weight hash; silent upstream changes are a new failure mode |

Three of the paper's own findings survive intact and drive the selection: **one context-heavy resident** (§5.7), **backbone divergence across pair-mates** (§5.6 Rung 3), and **quality per completed verified task as the only fitness function** (Law 1). Those three are the grounds below.

## 3. Cost model

Prices are per 1M tokens. One **unit** is a single call at 150,000 input and 15,000 output tokens — a repo-scale read with a substantial answer:

`unit cost = 0.15 × p_in + 0.015 × p_out`

An **organism task** is eight units: four stages, each an authoring call plus the mandatory mate read (§5.4 Rule 2, §7.6's ×2 floor). That is the ceiling; tasks touching fewer stages cost less, and prompt caching cuts the input term where the route offers it.

## 5. The tier that is not funded

Cost-effectiveness is a ratio, and the paper's fitness function supplies the denominator. These are the routes a premium tier would buy, with what they must deliver to earn it:

| Model | Unit | Organism task | Multiple over the registry | Must beat it by |
|---|---|---|---|---|
| `Qwen/Qwen3.8-Max` | $0.3218 | $2.57 | 18× | 18× on quality per completed verified task |
| `moonshotai/Kimi-K3` | $0.6412 | $5.13 | 37× | 37× |
| `anthropic/claude-opus-5` | $1.1250 | $9.00 | 64× | 64× |

No route clears that bar on a coding task. The correct use of the premium tier is as a **benchmark oracle** — a handful of golden-set items scored once per epoch to calibrate the cheap tier — not as a lane.

## 6. Falsifiers for this registry

Each row dies on evidence, per Law 4:

- **Pair fusion.** If Driver and Sentinel fall below the band floor on error-conditional disagreement (§7.5), the family separation is not doing the work: promote to a stronger divergent pair before adding a third witness.
- **Over-provisioning.** If `gpt-oss-20b` ($0.0066) matches `gpt-oss-120b` on golden-set items within the MDE, the Driver slot is paying for parameters it does not use. Demote, but keep the family separation.
- **Under-provisioning.** If the cheap pair's completed-task rate falls below the premium oracle's by more than the cost ratio, the registry is losing the mission to save the budget. Law 1 measures completed verified tasks, not tokens.
- **Context ceiling.** If F.4-equivalent measurement shows the Chronicle route truncates real transcripts, the served window — not the model — is wrong, and the 1M resident is replaced rather than supplemented.
- **Endpoint drift.** A golden-set regression on an unchanged route id means the provider changed the weights. That breaks Law 5's stamp, and the response is to pin a version or move the role.
- **Id disappearance.** Two model ids already configured in `~/.factory/settings.json` (`Qwen/Qwen3-Coder-30B-A3B-Instruct`, `MiniMaxAI/MiniMax-M2.1`) are absent from the snapshot. Every role needs a declared fallback route, and a fallback is a table entry, not a resident.

## 7. What this costs the constitution

The route is not free in the paper's terms, and the amendment should say so rather than let the ledger discover it:

1. **Law 1 is suspended in its local clause.** Paid dispatch is an emergency ration; a registry built on it makes the ration the diet, which is 9.8's theorem verbatim. The only lawful form is a recorded budget envelope per epoch with one `paid_dispatch` row per call, reconciled 1:1 — an authorization, not an assumption.
2. **Law 2's third axis is unmeasurable.** Bandwidth and NUMA pinning are provider-side; the paper's strongest hardware claim (§5.7) does not apply to a route. Q9 must be re-asked about cache eviction, not KV eviction.
3. **Rung 3's economics invert.** §5.6 orders the ladder by cost and puts backbone divergence last because it costs residency and thread share. On a route it costs neither, so the ladder's order should be restated: divergence first, instruction second, extra slices last (duplicate reads are the only rung that bills).
4. **Law 5's stamp weakens.** The claim schema records model and version; a route records a provider id, not a weight hash. Silent upstream updates are a new failure class with no local analogue.

Proposed for v2.4, not applied here: a new Appendix B row (B21, paid route as bootstrap substrate, *Re-scoped*), a D.5 route registry section, scope notes in §5.6, §5.7, and §14 Q8–Q9, and three Appendix A fields — `route_cost_usd_<role>`, `route_cache_hit_rate`, `route_version`. Under the repository rule, a registry change updates Appendix D and the affected §5.7/Q8–Q9 text together; this document is the input to that revision, not the revision.
